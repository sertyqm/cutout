Trace one image from click to download.

Your job is not to memorise FastAPI or JavaScript. Your job is to be able to point at an uploaded image and say where it is, what form it has, and which code owns it at every moment.

The path

1. FileThe browser gives JavaScript a File from the input or drop event.
2. RequestFormData packages it under the name image; fetch sends it.
3. ModelFastAPI reads it, validates it, creates a Pillow image, then calls the engine.
4. ResultThe endpoint returns PNG bytes. The browser turns those bytes into a temporary URL for preview and download.

The contract is the important part

The frontend and backend are separate programs. They only agree through a contract:

POST /api/remove-background
request: multipart/form-data, field name: image
response: image/png, body: PNG bytes

failure: JSON body, { "detail": "human-readable reason" }

If the field name changes in JavaScript but not Python, the request fails. If the backend returns JSON instead of PNG bytes, the preview and download fail. Most full-stack debugging is checking that this contract stayed true.

Find the four hand-offs in this repository

  1. In app/static/app.js, find where the browser gets a File.
  2. Find form.append("image", file). Why must "image" match Python?
  3. In app/main.py, find image: UploadFile = File(...). What is checked before the engine runs?
  4. Back in JavaScript, find response.blob() and URL.createObjectURL. Why does the browser not need to save a server file first?
